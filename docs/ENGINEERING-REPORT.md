# Stage 1 engineering report

## Status

The requested source implementation has been prepared. Stage 1 acceptance is
**pending a real Jekyll build and runtime verification**. The delivered visual
preview was rendered independently for design review, not generated by Jekyll.
Detailed passed and unverified checks are in `QA.md`.

## Scope delivered

Twelve page routes: home; thesis overview; five chapters; papers index; three
individual papers; and a 404 page. Each chapter has multiple sections, a
subsection, inline/display equation examples, two figures, at least two video
placeholders, captions, supplementary numbering, and previous/next navigation.
There are sixteen figure placements and twenty-one video placeholders across
chapters and papers. Chapter 4 and Paper 1 demonstrate three-way comparisons;
other pages demonstrate single and two-column presentations.

All academic titles, institutions, authors, venues, findings, and citations are
explicit placeholders. No scientific values, DOIs, real paper details, or video
content were invented. Optional PDF/code/DOI links are empty and non-clickable
until populated. A small, plainly labelled text file demonstrates downloads.

## Reuse, removal and additions

`TEMPLATE-ANALYSIS.md` gives the source-by-source analysis. The result retains the
AcademicPages profile/sidebar, masthead, palette, typography and archive rhythm,
while eliminating unused blog/portfolio infrastructure. Plain CSS replaces Sass
vendor grids without a separate build step. No bundled font files are included.
There are no custom Jekyll plugins and no JavaScript framework.

## Repository organization

Content: `index.md`, `thesis/index.md`, `papers/index.md`, `_chapters/`, `_papers/`.
Metadata: `_data/author.yml`, `thesis.yml`, `navigation.yml`, `videos.yml`.
Presentation: `_layouts/`, `_includes/`, `assets/css/`, `assets/js/`.
Static assets: `assets/images/`, `assets/posters/`, `assets/placeholders/`, `downloads/`.
Operations: `Gemfile`, `.ruby-version`, `_config.yml`, `.github/workflows/pages.yml`,
`scripts/check.rb`. Documentation and copyable starters are excluded from output.

There is intentionally no duplicate papers metadata list and no Python launcher.
Generated `_site` and locally installed gems are ignored by Git and not packaged
in the source archive. A separate design-preview archive is not source code and
should not be committed to this repository.

## Owner workflow

Full one-time macOS installation and PATH commands are in the README.
After installing Ruby/Bundler: `bundle install`, followed by
`bundle exec jekyll serve --livereload`.
Production: `JEKYLL_ENV=production bundle exec jekyll build`.
Validation: `bundle exec ruby scripts/check.rb`.

Add a chapter by copying `examples/chapter.md` into `_chapters/`, giving it a
unique `uid` and positive `chapter_number`, and adding its video records. Add a
paper similarly from `examples/paper.md`, with a unique `uid` and `order`.
Normal changes require Markdown/YAML, not editing layout HTML.

Figures use `figure.html` with source, visible number, anchor label, caption,
alt text, and optional layout/width/full-resolution link. Videos use `video.html`
with a YAML key. A blank `src` renders a real placeholder card instead of an
empty player. `video-group.html` provides two/three-column comparisons. Timed
caption and transcript fields are available for the future real videos.

## Deployment

The workflow validates source, builds at a root URL and test subpath, then
builds for the Pages origin/base path, uploads the static artifact, and deploys
on pushes to `main`. Pull requests validate but do not publish. It follows the
official Pages artifact/deploy architecture, with permissions scoped by job.
The workflow's YAML was checked; no GitHub Actions run or publication was made.

The owner must enable GitHub Actions in repository Pages settings, push the
source, and inspect the first workflow run. Custom-domain DNS is outside scope.

## Limitations and next actions

Obtain a successful original baseline where feasible, and a clean dependency
installation/build/serve of this adaptation. Verify live reload on the owner's
Mac, MathJax rendering with CDN access, Safari behavior, and a genuine GitHub
Pages deployment. Final accessibility and video playback require actual media.
The source checker is intentionally modest; it is not a full HTML or media
validation framework. No transcoding, external uploads, synchronous playback,
search, analytics, backend, or CMS has been implemented.

After technical acceptance and visual approval, Stage 2 should replace author
and thesis metadata, chapter/paper text, citations, real figures and captions.
Then choose a media host and test a small MP4/poster/caption sample before
processing the entire collection. The final switch to
`placeholder_mode: false` should happen only after all placeholders are replaced.
